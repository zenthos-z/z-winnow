content_enrich

写入: L2 parsed_contexts (不可变)
XML 解析 + Vision API 图片描述 + 链接预览 + Token 边界上下文分块
1. XML 沙箱解析 (11 种消息类型路由)
2. Vision API 图片 → 文本描述 (image_descriptions)
3. HTTP 预取链接 → 标题/摘要 (link_previews)
4. 卡片/引用/合并转发解析
5. S1 即时固化: INSERT parsed_contexts 到 SQLite (L2 层)
orchestrator
Phase C ~5-10s
输出: memory_context, report_types (validated)
验证 report_types + 加载 MemOS 上下文记忆包
1. 验证 report_types (默认 ["daily"])
2. LLM 生成 2-3 个语义搜索查询
3. MemOS topics cube 搜索 → historical_topics (top_k=5/query)
4. MemOS feedback cube 搜索 → prior_corrections
5. SQLite core_topics 表 → user_defined_topics
6. S3: MemOS 查询失败 → 流水中断 (必需服务)
unified_reporter
核心节点 Phase D ~30-60s
输出: unified_report (单次 LLM 调用)
S2 设计标准 — 单 Agent、单次 LLM 调用，产出所有报告内容
1. 合并 L2 增强消息 + 历史议题 + 用户预设议题
2. 加载 prior_corrections (RL 修正样本)
3. 单次 LLM 调用生成全部内容:
   • 日报概览 + 议题列表 (含 lifecycle)
   • 资源提取 (分类型)
   • 工程问题分析
   • 议题追踪 + 趋势摘要 + 生命周期分类
4. Mock 模式仅在 test 环境可用
output_composer
Phase E
